# 장바구니 기능

- **기능 이름:** `dev.ucp.shopping.cart`

## 개요

장바구니(Cart) 기능을 사용하면 체크아웃처럼 복잡한 절차 없이 장바구니를 구성할 수 있습니다. [체크아웃](https://dev-jonghoonpark.github.io/ucp-ko/draft/draft/specification/shopping/checkout/index.md)이 결제 핸들러, 상태 수명 주기, 주문 확정을 관리한다면, 장바구니는 구매 의사가 확정되기 전에 상품을 모아 두는 가벼운 CRUD 인터페이스를 제공합니다.

**장바구니와 체크아웃 중 무엇을 쓸까:**

- **장바구니**: 사용자가 상품을 둘러보고, 비교하고, 나중을 위해 저장하는 단계입니다. 결제 설정이 필요 없습니다. 플랫폼/에이전트가 상품을 자유롭게 추가, 삭제, 수정할 수 있습니다.
- **체크아웃**: 사용자가 구매 의사를 밝힌 단계입니다. 결제 핸들러가 설정되고 상태 수명 주기가 시작되며, 세션이 완료를 향해 진행됩니다.

일반적인 흐름: `cart session` → `checkout session` → `order`

장바구니가 지원하는 기능:

- **점진적 구성**: 여러 세션에 걸쳐 상품 추가/삭제
- **현지화된 예상 금액**: 전체 체크아웃 부담 없이 컨텍스트를 반영한 가격 책정
- **공유**: `continue_url`로 장바구니 공유와 복구 가능

## 장바구니와 체크아웃 비교

| 항목          | 장바구니                    | 체크아웃                              |
| ------------- | --------------------------- | ------------------------------------- |
| **목적**      | 구매 전 탐색                | 구매 확정                             |
| **결제**      | 없음                        | 필수(핸들러, 결제 수단)               |
| **상태**      | 이진(존재/찾을 수 없음)     | 수명 주기(`incomplete` → `completed`) |
| **완료 작업** | 없음                        | 있음                                  |
| **합계**      | 예상치(일부만 있을 수 있음) | 최종 가격                             |

## 장바구니에서 체크아웃으로 전환

장바구니 기능이 협상되었다면, 플랫폼은 체크아웃 생성(Create Checkout) 요청에 `cart_id`를 넣어 장바구니를 체크아웃으로 전환할 수 있습니다. 체크아웃 세션은 장바구니 내용(`line_items`, `context`, `buyer`)으로 초기화됩니다.

```json
{
  "cart_id": "cart_abc123",
  "line_items": []
}
```

장바구니 체크아웃 확장은 기본 체크아웃 스키마 위에 조합되므로 `line_items`는 여전히 필수 요청 필드입니다. 플랫폼은 반드시 line_items를 포함해야 하며(MUST), 값은 빈 배열 (`"line_items": []`)로 두어야 합니다(SHOULD). 비즈니스는 반드시 장바구니 내용을 사용해야 하며(MUST), 체크아웃 페이로드에서 겹치는 필드는 반드시 무시해야 합니다(MUST). `cart_id` 매개변수는 비즈니스 프로필에 장바구니 기능이 선언된 경우에만 사용할 수 있습니다.

**멱등 전환:**

해당 `cart_id`에 완료되지 않은 체크아웃이 이미 있으면, 비즈니스는 새로 만들지 말고 반드시 기존 체크아웃 세션을 반환해야 합니다(MUST). 이렇게 하면 장바구니마다 활성 체크아웃이 하나만 유지되어 세션 충돌을 막을 수 있습니다.

**전환 후 장바구니 수명 주기:**

`cart_id`로 체크아웃을 초기화했다면, 장바구니와 체크아웃 세션은 체크아웃이 진행되는 동안 연결된 상태여야 합니다(SHOULD).

- **체크아웃 진행 중** — 비즈니스는 장바구니를 유지하고, 관련된 체크아웃 수정 사항(수량 변경, 상품 삭제)을 장바구니에 다시 반영해야 합니다(SHOULD). 그래야 구매자가 체크아웃과 스토어프런트를 오가는 스토어프런트 복귀 흐름을 지원할 수 있습니다.
- **체크아웃 완료 후** — 비즈니스는 TTL, 체크아웃 완료, 기타 비즈니스 로직에 따라 장바구니를 비울 수 있습니다(MAY). 비워진 장바구니 ID로 이후 작업을 하면 `not_found`가 반환되며, 플랫폼은 `create_cart`로 새 세션을 시작할 수 있습니다.

## 수량과 판매 기준

장바구니 라인 아이템은 공통 [수량과 단위](https://dev-jonghoonpark.github.io/ucp-ko/draft/draft/specification/overview/#quantities-and-units) 규약을 따릅니다. 각 `line_items[].quantity`는 상품의 권한 있는 판매 기준에 따른 정수 단계 수입니다. 비즈니스 응답에 `line_items[].item.quantity_unit`이 없으면 기본값인 `each` 기준이라는 뜻이므로 `quantity`는 상품 개수를 나타냅니다.

플랫폼 요청에서 `line_items[].item.quantity_unit`을 생략하면 아무것도 주장하지 않은 것입니다. 비즈니스는 상품의 권한 있는 판매 기준으로 `quantity`를 해석하므로, 계량 단위로 판매되는 상품을 요청할 때도 `each`를 주장하는 일 없이 이 서술자를 생략할 수 있습니다. 판매 기준을 명시적으로 주장하려면 플랫폼은 `item.quantity_unit`을 포함할 수 있습니다(**MAY**).

판매 기준 디스커버리, 주장 일치 확인, 불일치 시 변환 또는 거부, 응답 반영, 주문 증분 처리, 라인 가격 책정은 [체크아웃 — 수량과 판매 기준](https://dev-jonghoonpark.github.io/ucp-ko/draft/draft/specification/shopping/checkout/#quantity-and-sale-basis)을 따릅니다. 장바구니 합계는 여전히 예상치입니다([합계](#total) 참고). 계량 단위 라인은 장바구니 요약에서 라인 아이템 하나로 계산되며, 이때 `quantity`는 상품 개수가 아니라 양입니다.

## 액션

장바구니는 처리되지 않은 액션(Action) 인스턴스를 응답 전용 `actions` 맵으로 노출합니다. 이 맵은 [개요 — 액션](https://dev-jonghoonpark.github.io/ucp-ko/draft/draft/specification/overview/#actions)에 정의되어 있습니다.

장바구니에는 상태 수명 주기가 없습니다. 각 액션은 해당 액션 유형에 지정된 장바구니 효과만 제한합니다. 비즈니스는 처리되지 않은 액션이 있다는 이유로 관련 없는 장바구니 작업을 거부해서는 안 됩니다(**MUST NOT**). 플랫폼은 액션이 처리되지 않은 동안에도 상품을 계속 추가, 삭제, 수정할 수 있습니다(**MAY**).

액션을 처리한 뒤 플랫폼은 [장바구니 조회](#get-cart)나 이후의 수정 응답으로 최신 장바구니를 가져와야 합니다(**SHOULD**).

스코프 선언과 도출, 사용자 정의 스코프로 이 집합을 확장하는 규칙은 [신원 연결 — 스코프](https://dev-jonghoonpark.github.io/ucp-ko/draft/draft/specification/common/identity-linking/#scopes)에 정의되어 있습니다.

## 지침

### 플랫폼

- 구매 전 탐색과 세션 유지에 장바구니를 사용할 수 있습니다(**MAY**).
- 사용자가 구매 의사를 밝히면 장바구니를 체크아웃으로 전환해야 합니다(**SHOULD**).
- 비즈니스 UI로 넘기기 위해 `continue_url`을 표시할 수 있습니다(**MAY**).
- 장바구니가 만료되거나 취소되었을 때 반환되는 `not_found`를 적절히 처리해야 합니다(**SHOULD**).

### 비즈니스

- 장바구니 인계와 세션 복구를 위해 `continue_url`을 제공해야 합니다(**SHOULD**).
- TODO: `continue_url` 목적지 논의 필요 - 장바구니 vs 체크아웃.
- 계산할 수 있으면 예상 합계를 제공해야 합니다(**SHOULD**).
- 주소를 모르면 체크아웃 전까지 풀필먼트 합계를 생략할 수 있습니다(**MAY**).
- 유효성 검사 경고가 있으면 정보성 메시지를 반환해야 합니다(**SHOULD**).
- `expires_at`으로 장바구니 만료 시점을 설정할 수 있습니다(**MAY**).
- `cart_id`로 체크아웃을 초기화한 경우 [장바구니 수명 주기 요구 사항](#cart-to-checkout-conversion)을 따라야 합니다(**SHOULD**).

## 작업

장바구니 기능에서 정의하는 논리적 작업은 다음과 같습니다.

| 작업                           | 설명                                    |
| ------------------------------ | --------------------------------------- |
| **장바구니 생성(Create Cart)** | 새 장바구니 세션을 만듭니다.            |
| **장바구니 조회(Get Cart)**    | 장바구니 세션의 현재 상태를 가져옵니다. |
| **장바구니 수정(Update Cart)** | 장바구니 세션을 수정합니다.             |
| **장바구니 취소(Cancel Cart)** | 장바구니 세션을 취소합니다.             |

### 장바구니 생성

라인 아이템과 선택적 구매자/컨텍스트 정보로 새 장바구니 세션을 만듭니다. 구매자/컨텍스트 정보는 현지화된 예상 가격을 계산하는 데 쓰입니다.

요청한 상품을 **하나도** 구매할 수 없으면, 비즈니스는 장바구니 리소스를 만드는 대신 오류 응답을 반환할 수 있습니다(MAY). 주 판별 기준은 `ucp.status`이며, `id`가 없다는 점도 일관된 보조 지표가 됩니다.

```json
{
  "ucp": { "version": "draft", "status": "error" },
  "messages": [
    {
      "type": "error",
      "code": "out_of_stock",
      "content": "All requested items are currently out of stock",
      "severity": "unrecoverable"
    }
  ],
  "continue_url": "https://merchant.com/"
}
```

- [REST 바인딩](https://dev-jonghoonpark.github.io/ucp-ko/draft/draft/specification/shopping/cart/rest/#create-cart)
- [MCP 바인딩](https://dev-jonghoonpark.github.io/ucp-ko/draft/draft/specification/shopping/cart/mcp/#create_cart)

### 장바구니 조회

장바구니 세션의 최신 상태를 가져옵니다. 장바구니가 없거나, 만료되었거나, 취소되었으면 `not_found`를 반환합니다.

- [REST 바인딩](https://dev-jonghoonpark.github.io/ucp-ko/draft/draft/specification/shopping/cart/rest/#get-cart)
- [MCP 바인딩](https://dev-jonghoonpark.github.io/ucp-ko/draft/draft/specification/shopping/cart/mcp/#get_cart)

### 장바구니 수정

장바구니 세션을 통째로 교체합니다. 플랫폼은 반드시 장바구니 리소스 전체를 보내야 합니다(**MUST**). 보낸 리소스가 비즈니스 측의 기존 장바구니 상태를 대체합니다.

- [REST 바인딩](https://dev-jonghoonpark.github.io/ucp-ko/draft/draft/specification/shopping/cart/rest/#update-cart)
- [MCP 바인딩](https://dev-jonghoonpark.github.io/ucp-ko/draft/draft/specification/shopping/cart/mcp/#update_cart)

### 장바구니 취소

장바구니 세션을 취소합니다. 비즈니스는 반드시 삭제 전의 장바구니 상태를 반환해야 합니다(MUST). 이후 이 장바구니 ID로 들어오는 작업에는 `not_found`를 반환해야 합니다(SHOULD).

- [REST 바인딩](https://dev-jonghoonpark.github.io/ucp-ko/draft/draft/specification/shopping/cart/rest/#cancel-cart)

### 어트리뷰션

플랫폼이 제공하는 유입 경로와 전환 이벤트 컨텍스트입니다. 플랫폼이 전달하는 캠페인 ID, 클릭 식별자, 소스/매체 표식이 여기에 해당합니다. 자세한 내용과 동의 요구 사항은 [어트리뷰션](https://dev-jonghoonpark.github.io/ucp-ko/draft/draft/specification/overview/#attribution)을 참고하세요.

플랫폼이 내보내는 추천 및 전환 이벤트 맥락: 캠페인 식별자, 클릭 ID, source/medium 마커 등. 브라우저 기반 흐름에서 플랫폼이 URL 쿼리 매개변수로 전달하는 것과 같은 매개변수입니다.

| display_text | string                                                                      | 선택      | 금액 옆에 표시할 텍스트. 적절한 방식을 반영해야 합니다(예: 'Shipping', 'Delivery').                                                                                                                                         |
| amount       | [Signed Amount](/ucp-ko/draft/draft/specification/reference/#signed-amount) | **필수**  | ISO 4217에 정의된 통화의 최소 단위로 나타낸 금액. 최소 단위와 기본 단위의 비율은 통화의 지수를 참고합니다(예: USD는 2, JPY는 0, KWD는 3). 음수일 수 있으며, 부호는 값 자체에 포함됩니다(예: 할인은 음수, 청구 금액은 양수). |

세금은 계산할 수 있으면 포함할 수 있습니다(MAY). 플랫폼은 장바구니 합계를 예상치로 보아야 하며(SHOULD), 정확한 세금은 체크아웃에서 계산됩니다.

### 정책

이 장바구니의 상품에 적용되는 정책(반품/환불 조건, 보증 등)입니다. `applies_to`의 JSONPath 대상은 이 응답의 루트를 기준으로 합니다(예: `$.line_items[0]`). 전체 모델은 [정책](https://dev-jonghoonpark.github.io/ucp-ko/draft/draft/specification/overview/#policies)을 참고하세요.

| 이름        | 타입                                                                                    | 필수 여부 | 설명                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ----------- | --------------------------------------------------------------------------------------- | --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| type        | [Reverse Domain Name](/ucp-ko/draft/draft/specification/reference/#reverse-domain-name) | **필수**  | 정책 유형 판별자. 열린 역 DNS 어휘입니다. 잘 알려진 정책 유형의 레지스트리는 명세 문서를 참고하세요. 비즈니스는 자체 도메인에 사용자 정의 유형을 정의할 수 있습니다(MAY, 예: `com.example.policy.price_match`). 플랫폼은 알 수 없는 값을 반드시 허용해야 합니다(MUST).                                                                                                                                                                                                                                                                                                                                                   |
| description | [Description](/ucp-ko/draft/draft/specification/reference/#description)                 | **필수**  | 하나 이상의 형식(plain, markdown, html)으로 된 사람이 읽을 수 있는 정책 요약. 플랫폼이 유형별 필드를 이해하지 못해도 표시할 수 있도록 모든 정책에 필수입니다. 이것은 구매자 대상 고지가 아닙니다. 표시 의무는 `messages[]` 경고로 부과됩니다(정책 섹션 참고).                                                                                                                                                                                                                                                                                                                                                            |
| applies_to  | Array[string]                                                                           | 선택      | 이 정책이 적용되는 노드를 가리키는 RFC 9535 JSONPath 표현식으로, 응답을 포함하는 루트를 기준으로 합니다(예: 장바구니·체크아웃의 `$.line_items[0]`, 카탈로그의 `$.products[2]`). 각 대상은 지정한 노드와 그 아래에 중첩된 모든 것을 포함하므로, 상품을 대상으로 하면 그 변형도 포함됩니다. 단수 쿼리(RFC 9535 Section 2.3.5.1, 이름·인덱스 선택자만 사용)는 노드 하나를 지정하고, 필터·와일드카드·슬라이스는 노드 집합과 일치합니다. 생략하면 정책이 응답 전체에 적용됩니다. 같은 `type`의 정책들이 한 노드를 두고 경합하면 가장 좁은 대상이 이기고 나머지를 덮어씁니다. 구체성을 판정하는 방법은 정책 섹션을 참고하세요. |
| url         | string                                                                                  | 선택      | 전체 정책 문서 링크(선택 사항).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
