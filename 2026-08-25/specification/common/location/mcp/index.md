# Location - MCP 바인딩

이 문서는 [Location 기능(Capability)](https://dev-jonghoonpark.github.io/ucp-ko/2026-08-25/2026-08-25/specification/common/location/index.md)의 Model Context Protocol(MCP) 바인딩을 설명합니다.

## 프로토콜 기본 사항

### 디스커버리

비즈니스는 `/.well-known/ucp`의 UCP 프로필에서 Common 서비스와 Location 기능의 MCP 전송 방식 지원 여부를 알립니다.

```json
{
  "ucp": {
    "version": "2026-08-25",
    "services": {
      "dev.ucp.common": [
        {
          "version": "2026-08-25",
          "spec": "https://ucp.dev/2026-08-25/specification/overview",
          "transport": "mcp",
          "schema": "https://ucp.dev/2026-08-25/services/common/mcp.openrpc.json",
          "endpoint": "https://business.example.com/ucp/mcp"
        }
      ]
    },
    "capabilities": {
      "dev.ucp.common.location.search": [{
        "version": "2026-08-25",
        "spec": "https://ucp.dev/2026-08-25/specification/common/location/search",
        "schema": "https://ucp.dev/2026-08-25/schemas/common/location_search.json"
      }],
      "dev.ucp.common.location.lookup": [{
        "version": "2026-08-25",
        "spec": "https://ucp.dev/2026-08-25/specification/common/location/lookup",
        "schema": "https://ucp.dev/2026-08-25/schemas/common/location_lookup.json"
      }]
    },
    "payment_handlers": {}
  }
}
```

### 요청 메타데이터

MCP를 사용하는 플랫폼은 모든 요청에 반드시 `meta["ucp-agent"].profile`이 포함된 `meta` 객체를 넣어야 합니다(**MUST**). 이 필드는 버전 호환성 확인과 기능 협상에 쓰이는 플랫폼의 UCP 프로필을 식별합니다. 프로토콜 메타데이터는 `location`의 도메인 요청과 분리해 `meta`에 둡니다.

## 도구

| 도구               | 기능                                                                                                                    | 설명                                                                                             |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| `search_locations` | [Search](https://dev-jonghoonpark.github.io/ucp-ko/2026-08-25/2026-08-25/specification/common/location/search/index.md) | 텍스트, 명시적 공간 관계, 필터로 Location을 검색합니다.                                          |
| `lookup_locations` | [Lookup](https://dev-jonghoonpark.github.io/ucp-ko/2026-08-25/2026-08-25/specification/common/location/lookup/index.md) | 식별자로 Location을 일괄 조회하며, 선택적으로 명시적 공간 관계와 필터로 범위를 좁힐 수 있습니다. |

### `search_locations`

[Location Search](https://dev-jonghoonpark.github.io/ucp-ko/2026-08-25/2026-08-25/specification/common/location/search/index.md) 기능에 대응합니다. [전송 방식에 중립적인 Search 전체 예시](https://dev-jonghoonpark.github.io/ucp-ko/2026-08-25/2026-08-25/specification/common/location/search/#examples)를 참고하세요.

#### 요청 인자

위치 검색 요청 본문입니다. `distance`와 `serves` 관계, 그리고 제공된 모든 `filters` 조건은 AND로 결합되며, `query`가 이를 완화하지 않습니다.

| 이름       | 타입   | 필수 여부 | 설명                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ---------- | ------ | --------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| query      | string | 선택      | 자연어 위치 검색을 위한 자유 텍스트 검색어(예: 'restaurants near me that deliver', 'hotels with pool').                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| context    | object | 선택      | 관련성 판단과 현지화를 위한 잠정적 구매자 신호로, 권위 있는 데이터가 아닙니다. 검증된 입력(예: 배송 주소)이 없으면 비즈니스는 이 값을 사용해야 하며(SHOULD), 더 신뢰도 높은 신호(인증된 계정, 위험 탐지)나 규제 제약(수출 통제)과 맞지 않으면 무시하거나 우선순위를 낮출 수 있습니다(MAY). 자격 판단과 정책 적용은 반드시 체크아웃 시점에 구속력 있는 거래 데이터로 수행해야 합니다(MUST). 컨텍스트는 개인을 식별할 수 없어야 하며(SHOULD), 단계적으로 공개할 수 있습니다. 초기에는 대략적인 신호를, 세션이 진행되면서 더 세밀한 정보를 제공합니다. 더 세밀한 데이터(배송 주소, 청구 주소)가 컨텍스트보다 우선합니다. |
| signals    | object | 선택      | 승인과 악용 방지를 돕기 위해 플랫폼이 제공하는 환경 데이터. 값은 구매자가 주장한 내용이어서는 안 됩니다(MUST NOT). 플랫폼은 직접 관찰했거나 독립적으로 검증 가능한 제3자 증명에 근거한 신호를 제공합니다. 여러 확장이 공유 네임스페이스에 값을 추가할 때 출처를 보장하고 충돌을 막기 위해, 모든 신호 키는 반드시 역도메인 이름을 사용해야 합니다(MUST).                                                                                                                                                                                                                                                               |
| distance   | object | 선택      | 명시적 중심점 반경 조건(선택 사항). 있으면 `serves` 및 제공된 모든 `filters` 조건과 AND로 결합됩니다.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| serves     | object | 선택      | 권위 있는 서비스 대상 조건(선택 사항). 있으면 `distance` 및 제공된 모든 `filters` 조건과 AND로 결합됩니다.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| filters    | object | 선택      | 위치 검색과 조회 결과를 좁히는 필터 조건. 제공된 모든 필터는 AND로 결합됩니다.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| pagination | object | 선택      | 요청의 페이지네이션 매개변수.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |

#### 응답 스키마

| 이름       | 타입          | 필수 여부 | 설명                                      |
| ---------- | ------------- | --------- | ----------------------------------------- |
| ucp        | any           | **필수**  | 위치 응답용 UCP 메타데이터.               |
| locations  | Array[object] | **필수**  | 검색 조건에 맞는 위치.                    |
| pagination | object        | 선택      | 응답의 페이지네이션 정보.                 |
| messages   | Array[object] | 선택      | 검색 결과에 관한 오류, 경고, 정보 메시지. |

#### 바인딩 엔벌로프 예시

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "search_locations",
    "arguments": {
      "meta": {
        "ucp-agent": {
          "profile": "https://platform.example/profiles/v2026-01/agent.json"
        }
      },
      "location": {
        "query": "grocery store"
      }
    }
  }
}
```

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "structuredContent": {
      "ucp": {
        "version": "2026-08-25",
        "capabilities": {
          "dev.ucp.common.location.search": [
            {"version": "2026-08-25"}
          ]
        }
      },
      "locations": [
        {
          "id": "loc_valley_grocers",
          "name": "Valley Grocers"
        }
      ]
    }
  }
}
```

### `lookup_locations`

[Location Lookup](https://dev-jonghoonpark.github.io/ucp-ko/2026-08-25/2026-08-25/specification/common/location/lookup/index.md) 기능에 대응합니다. [전송 방식에 중립적인 Lookup 전체 예시](https://dev-jonghoonpark.github.io/ucp-ko/2026-08-25/2026-08-25/specification/common/location/lookup/#examples)를 참고하세요.

#### 요청 인자

일괄 위치 조회 요청 본문입니다. 비즈니스는 `distance`, `serves`와 제공된 모든 `filters` 조건을 적용하기 전에 `ids`를 해석하고 중복을 제거합니다. 모든 구조화된 조건은 AND로 결합됩니다.

| 이름     | 타입          | 필수 여부 | 설명                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| -------- | ------------- | --------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ids      | Array[string] | **필수**  | 조회할 위치의 식별자. 비즈니스는 반드시 정규 `Location.id` 값을 지원해야 하며(MUST), 보조 식별자나 별칭 식별자를 지원할 수 있습니다(MAY).                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| distance | object        | 선택      | ID 확인 후에 적용되는 명시적 중심점 반경 조건(선택 사항). `serves` 및 제공된 모든 `filters` 조건과 AND로 결합됩니다.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| serves   | object        | 선택      | ID 확인 후에 적용되는 권위 있는 서비스 대상 조건(선택 사항). `distance` 및 제공된 모든 `filters` 조건과 AND로 결합됩니다.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| filters  | object        | 선택      | 위치 검색과 조회 결과를 좁히는 필터 조건. 제공된 모든 필터는 AND로 결합됩니다.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| context  | object        | 선택      | 관련성 판단과 현지화를 위한 잠정적 구매자 신호로, 권위 있는 데이터가 아닙니다. 검증된 입력(예: 배송 주소)이 없으면 비즈니스는 이 값을 사용해야 하며(SHOULD), 더 신뢰도 높은 신호(인증된 계정, 위험 탐지)나 규제 제약(수출 통제)과 맞지 않으면 무시하거나 우선순위를 낮출 수 있습니다(MAY). 자격 판단과 정책 적용은 반드시 체크아웃 시점에 구속력 있는 거래 데이터로 수행해야 합니다(MUST). 컨텍스트는 개인을 식별할 수 없어야 하며(SHOULD), 단계적으로 공개할 수 있습니다. 초기에는 대략적인 신호를, 세션이 진행되면서 더 세밀한 정보를 제공합니다. 더 세밀한 데이터(배송 주소, 청구 주소)가 컨텍스트보다 우선합니다. |
| signals  | object        | 선택      | 승인과 악용 방지를 돕기 위해 플랫폼이 제공하는 환경 데이터. 값은 구매자가 주장한 내용이어서는 안 됩니다(MUST NOT). 플랫폼은 직접 관찰했거나 독립적으로 검증 가능한 제3자 증명에 근거한 신호를 제공합니다. 여러 확장이 공유 네임스페이스에 값을 추가할 때 출처를 보장하고 충돌을 막기 위해, 모든 신호 키는 반드시 역도메인 이름을 사용해야 합니다(MUST).                                                                                                                                                                                                                                                               |

#### 응답 스키마

| 이름      | 타입            | 필수 여부 | 설명                                                                                                                                                                                                                                                                     |
| --------- | --------------- | --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| ucp       | any             | **필수**  | 위치 응답용 UCP 메타데이터.                                                                                                                                                                                                                                              |
| locations | Array[Location] | **필수**  | 요청한 식별자와 세부 조건에 맞는 위치. 일부 식별자가 해석되지 않거나 해석된 위치가 필터링되면 더 적을 수 있고, 하나의 식별자가 여러 위치로 해석되면 더 많을 수 있습니다. 여러 식별자가 같은 위치로 해석되면 반환되는 위치 하나에 해당하는 `inputs` 항목이 모두 담깁니다. |
| messages  | Array[object]   | 선택      | 요청된 위치에 관한 오류, 경고, 정보 메시지. 비즈니스가 설정된 최대 개수만큼만 식별자를 처리할 때의 `batch_limit_applied`도 포함합니다.                                                                                                                                   |

## 오류 처리

UCP는 전송 수준 오류와 비즈니스 결과를 구분하는 2계층 오류 모델을 사용합니다.

### 전송 오류

요청 처리를 막는 전송 수준 실패(인증, 요청 한도 제한, 잘못된 파라미터)는 JSON-RPC `error`로 반환합니다. 자세한 내용은 [핵심 명세](https://dev-jonghoonpark.github.io/ucp-ko/2026-08-25/2026-08-25/specification/overview/#error-codes)를 참고하세요.

### 비즈니스 결과

모든 애플리케이션 수준 결과는 UCP 엔벌로프와 선택적 `messages` 배열을 담은 성공 JSON-RPC result로 반환합니다. 메시지의 의미는 [Location 개요](https://dev-jonghoonpark.github.io/ucp-ko/2026-08-25/2026-08-25/specification/common/location/#messages-and-error-handling)를 참고하세요.

## 엔티티

### Amenity Type

| 이름                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | 타입 | 필수 여부 | 설명 |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---- | --------- | ---- |
| 기능, 서비스, 핸들러, 자격 클레임, 확장이 추가한 키에 충돌 없는 네임스페이스를 부여하는 역도메인 식별자입니다. 점으로 구분된 세그먼트가 두 개 이상 있어야 합니다(예: 'dev.ucp.shopping.checkout', 'com.example.loyalty_gold'). 첫 번째 이후의 세그먼트는 도메인이나 식별자에서 파생되므로 중간에 하이픈을 포함하거나 숫자로 시작하거나 밑줄을 포함할 수 있지만(예: 'com.example-shop.checkout', 'com.2example.cart', 'dev.ucp.common.identity_linking'), 하이픈으로 시작하거나 끝나서는 안 됩니다. 첫 번째 세그먼트(뒤집힌 최상위 도메인)는 문자와 숫자로 이루어지며, 'xn--p1ai' 같은 국제화(punycode) 최상위 도메인을 지원하기 위해 중간에 하이픈을 포함할 수 있습니다. |      |           |      |

**패턴:** `^[a-z](?:[a-z0-9-]*[a-z0-9])?(?:\.[a-z0-9](?:[a-z0-9_-]*[a-z0-9_])?)+$`

### Amenity

편의 시설 식별자 하나에 대한 구매자용 표시 메타데이터. 편의 시설의 식별과 필터 매칭은 이 메타데이터가 아니라 이를 담고 있는 맵의 키가 정의합니다.

| 이름        | 타입   | 필수 여부 | 설명                                                                                                                                                                                                                                              |
| ----------- | ------ | --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| description | string | **필수**  | 편의시설을 나타내는 짧은 일반 텍스트 구매자용 레이블 또는 문구로, 간결한 목록에 바로 쓸 수 있습니다(예: 'Curbside pickup'). 비즈니스는 가능하면 요청에 맞게 현지화해야 합니다(SHOULD). 이 내용은 편의시설 식별이나 필터 일치에 관여하지 않습니다. |

### Lookup Location

조회 응답용으로 필수 연계 메타데이터를 포함한 위치.

| 이름            | 타입          | 필수 여부 | 설명                                                                                                                                                                                                                                                                                                                 |
| --------------- | ------------- | --------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| id              | string        | **필수**  | 비즈니스 범위의 안정적이고 불투명한 위치 식별자.                                                                                                                                                                                                                                                                     |
| name            | string        | **필수**  | 구매자에게 표시되는, 비즈니스가 소유한 표시 이름.                                                                                                                                                                                                                                                                    |
| address         | object        | 선택      | 장소의 실제 주소.                                                                                                                                                                                                                                                                                                    |
| geo             | object        | 선택      | 위치의 지리 좌표.                                                                                                                                                                                                                                                                                                    |

## 적합성

적합한 MCP 전송 방식 구현은 반드시 다음을 지켜야 합니다(**MUST**).

1. JSON-RPC 2.0 프로토콜을 올바르게 구현합니다.
1. 비즈니스의 UCP 프로필에 알린 각 Location 기능의 도구를 해당 기능의 요구 사항([Search](https://dev-jonghoonpark.github.io/ucp-ko/2026-08-25/2026-08-25/specification/common/location/search/index.md), [Lookup](https://dev-jonghoonpark.github.io/ucp-ko/2026-08-25/2026-08-25/specification/common/location/lookup/index.md))에 따라 구현합니다. 각 기능은 독립적으로 채택할 수 있습니다(**MAY**).
1. `distance`, `serves` 관계와 `filters.items` 재고 조건은 플랫폼이 명시적으로 제공한 피연산자로만 평가합니다. `context`, `signals`, IP 주소에서 피연산자를 유도해서는 안 되며, 입력이 없을 때 서비스 가능 여부나 상품 재고 여부를 암묵적으로 확인해서도 안 됩니다.
1. `distance`, `serves`, 그리고 제공된 모든 `filters` 조건을 논리곱(AND)으로 적용합니다.
1. 공통 페이지네이션 규약에 따라 Search에서 커서 기반 페이지네이션을 지원합니다([페이지네이션](https://dev-jonghoonpark.github.io/ucp-ko/2026-08-25/2026-08-25/specification/common/location/search/#pagination) 참고).
1. Lookup 요청에는 성공 JSON-RPC result를 반환합니다. 알 수 없는 식별자가 있으면 반환되는 Location이 줄거나 없을 뿐입니다(`messages` 배열에 정보성 `not_found` 메시지를 포함할 수 있습니다(**MAY**)).
1. Lookup 요청이 비즈니스의 배치 최대치를 초과하면 성공 JSON-RPC result를 반환하고, 요청 순서대로 고유 식별자를 최대치만큼 앞에서부터 처리하며, 정보성 `batch_limit_applied` 메시지를 포함합니다.
1. 도구 입력을 UCP 스키마로 검증합니다.
