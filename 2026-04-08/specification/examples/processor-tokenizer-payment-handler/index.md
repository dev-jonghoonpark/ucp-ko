# 프로세서 토크나이저 결제 핸들러

- **핸들러 이름:** `com.example.processor_tokenizer`
- **유형:** 결제 핸들러 예시

## 소개

이 핸들러는 **"Tokenize to Process"** 흐름을 구현합니다. 이 흐름에서는 토큰을 생성하는 주체(토크나이저)와 최종 결제를 처리하는 주체(프로세서)가 같습니다.

**참고:** 이 예시는 카드 자격 증명을 사용하지만, 이 패턴은 **모든 자격 증명 유형**에 적용됩니다. 컴플라이언스 요구 사항은 자격 증명 유형에 따라 다릅니다(예: 카드는 PCI DSS).

이 명세는 흔히 쓰이는 두 가지 구현 시나리오를 함께 다룹니다.

1. **비즈니스 호스팅:** 엔터프라이즈 비즈니스가 자체 보안 볼트를 호스팅합니다. 비즈니스가 토큰화와 처리를 모두 맡습니다.
1. **PSP 호스팅:** 비즈니스가 서드파티 PSP를 사용합니다. PSP가 토큰화와 처리를 모두 맡습니다.

두 경우 모두 **API로 역토큰화하는 단계가 필요 없습니다**. 토큰 해석은 프로세서의 보안 환경 안에서 이루어집니다.

### 시나리오 비교

| 항목                  | 시나리오 A: PSP 호스팅                | 시나리오 B: 비즈니스 호스팅       |
| --------------------- | ------------------------------------- | --------------------------------- |
| **토크나이저 호스트** | 서드파티 PSP                          | 비즈니스                          |
| **컴플라이언스 범위** | **낮음** (비즈니스가 PAN을 보지 않음) | **높음** (비즈니스가 PAN을 저장)  |
| **신원 바인딩**       | **필수** (PSP에 판매자 식별자 필요)   | **암묵적** (비즈니스가 자신을 앎) |

## 참여자

| 참여자                    | 역할                                                                                                  | 사전 요구 사항                                     |
| ------------------------- | ----------------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| **토크나이저 / 프로세서** | `/tokenize` 엔드포인트를 호스팅하고, 토큰을 저장하며, 결제를 처리합니다(비즈니스 또는 PSP일 수 있음). | 자격 증명 유형별 컴플라이언스(예: 카드는 PCI DSS). |
| **플랫폼**                | 보안 자격 증명 제공자로 자격 증명을 수집하고, 토크나이저를 호출하며, 체크아웃을 제출합니다.           | 보안 자격 증명 제공자.                             |
| **비즈니스**              | 체크아웃에 사용할 핸들러를 구성합니다.                                                                | 없음(PSP 호스팅인 경우).                           |

### 패턴 흐름

```text
+------------+                         +-----------------------------------+
|  Platform  |                         |       Tokenizer / Processor       |
| (Collector)|                         |      (Business or PSP)            |
+-----+------+                         +-----------------+-----------------+
      |                                                  |
      |  1. GET ucp.payment_handlers                     |
      |------------------------------------------------->|
      |                                                  |
      |  2. Handler Config (URL + Identity)              |
      |<-------------------------------------------------|
      |                                                  |
      |  3. POST /tokenize (Credential + Identity)       |
      |------------------------------------------------->|
      |                                                  |
      |  4. Token                                        |
      |<-------------------------------------------------|
      |                                                  |
      |  5. POST checkout with TokenCredential           |
      |------------------------------------------------->|
      |                                                  |
      |        (Internal Resolution: Token -> Info)      |
      |                                                  |
      |  6. Payment Result                               |
      |<-------------------------------------------------|
```

## 구성

비즈니스는 UCP 프로필의 `payment_handlers` 레지스트리에 이 핸들러를 알립니다. 플랫폼이 "PSP 모드"(신원 전송)로 동작할지 "직접 모드"(암묵적 신원)로 동작할지는 이 구성에 따라 정해집니다.

### 비즈니스 구성(디스커버리)

비즈니스는 디스커버리 과정에서 토큰화 엔드포인트와 신원을 알립니다. `/tokenize` 엔드포인트 URL은 핸들러 명세(`spec` 필드로 참조)에 나와 있습니다.

| 필드          | 타입   | 필수 | 설명                                  |
| ------------- | ------ | ---- | ------------------------------------- |
| `environment` | string | 예   | API 환경(`sandbox` 또는 `production`) |
| `business_id` | string | 예   | 프로세서에 등록된 비즈니스 식별자     |

#### 비즈니스 핸들러 선언 예시

```json
{
  "ucp": {
    "version": "2026-04-08",
    "payment_handlers": {
      "com.example.processor_tokenizer": [
        {
          "id": "processor_tokenizer",
          "version": "2026-04-08",
          "spec": "https://example.com/ucp/processor-tokenizer.json",
          "schema": "https://example.com/ucp/processor-tokenizer/schema.json",
          "available_instruments": [
            {
              "type": "card",
              "constraints": {
                "brands": ["visa", "mastercard", "amex"]
              }
            }
          ],
          "config": {
            "environment": "production",
            "business_id": "merchant_xyz789"
          }
        }
      ]
    }
  }
}
```

### 응답 구성(체크아웃)

응답 구성에는 이 체크아웃에서 사용할 수 있는 항목의 런타임 정보가 들어 있습니다.

| 필드          | 타입   | 필수 | 설명                            |
| ------------- | ------ | ---- | ------------------------------- |
| `environment` | string | 예   | 이 체크아웃에 사용되는 API 환경 |
| `business_id` | string | 예   | 비즈니스 식별자                 |

#### 응답 구성 예시

```json
{
  "id": "processor_tokenizer",
  "version": "2026-04-08",
  "available_instruments": [
    {
      "type": "card",
      "constraints": {
        "brands": ["visa", "mastercard", "amex"]
      }
    }
  ],
  "config": {
    "environment": "production",
    "business_id": "merchant_xyz789"
  }
}
```

## 플랫폼 연동

### 사전 요구 사항

이 핸들러를 사용하기 전에 플랫폼은 다음을 갖춰야 합니다.

1. 사용자로부터 민감한 결제 데이터를 수집하는 **컴플라이언스를 준수하는 보안 결제 자격 증명 제공자**에 접근할 수 있어야 합니다. 이 서비스는 처리하는 결제 수단의 컴플라이언스 요구 사항(예: PCI DSS)을 충족해야 합니다.
1. 핸들러 구성에 정의된 특정 `endpoint`를 호출할 권한이 있는 인증 자격 증명(예: API 키)을 발급받아야 합니다.

**사전 요구 사항 결과물:**

| 항목                  | 설명                                                                                |
| --------------------- | ----------------------------------------------------------------------------------- |
| 결제 자격 증명 제공자 | 사용자로부터 민감한 결제 데이터를 수집하는, **컴플라이언스를 준수하는** 보안 서비스 |
| 인증 자격 증명        | `/tokenize` 호출을 인증하기 위한 API 키 또는 OAuth 토큰                             |

### 결제 프로토콜

#### 1단계: 핸들러 디스커버리

플랫폼은 프로세서 토크나이저 핸들러를 식별하고 비즈니스의 구성을 가져옵니다.

```json
{
  "ucp": {
    "payment_handlers": {
      "com.example.processor_tokenizer": [
        {
          "id": "processor_tokenizer",
          "version": "2026-04-08",
          "available_instruments": [
            {"type": "card", "constraints": {"brands": ["visa", "mastercard", "amex"]}}
          ],
          "config": {
            "environment": "production",
            "business_id": "merchant_xyz789"
          }
        }
      ]
    }
  }
}
```

#### 2단계: 민감한 데이터 수집

플랫폼의 **컴플라이언스를 준수하는 보안 결제 자격 증명 제공자**가 사용자로부터 민감한 결제 데이터를 수집합니다. 예를 들어 민감한 결제 수단 정보가 플랫폼을 절대 거치지 않도록 보장하는, 컴플라이언스를 준수하는 결제 폼을 사용합니다.

#### 3단계: 데이터 토큰화

플랫폼의 결제 자격 증명 제공자가 구성된 `endpoint`를 호출합니다.

**참고:** 핸들러 구성에 `identity` 객체가 포함되어 있으면, 자격 증명 제공자는 반드시 이를 `binding` 객체에 넣어야 합니다(**MUST**).

응답:

```json
{
  "token": "tok_a1b2c3d4e5f6"
}
```

### 4단계: 체크아웃 완료

플랫폼이 토큰을 제출합니다.

```json
POST /checkout-sessions/{checkout_id}/complete
UCP-Agent: profile="https://platform.example/profile"
Content-Type: application/json

{
  "payment": {
    "instruments": [
      {
        "id": "instr_1",
        "handler_id": "processor_tokenizer",
        "type": "card",
        "selected": true,
        "display": {
          "brand": "visa",
          "last_digits": "1111",
          "expiry_month": 12,
          "expiry_year": 2026
        },
        "credential": {
          "type": "token",
          "token": "tok_a1b2c3d4e5f6"
        }
      }
    ]
  },
  "signals": {
    "dev.ucp.buyer_ip": "203.0.113.42",
    "dev.ucp.user_agent": "Mozilla/5.0 ..."
  }
}
```

## 구현 가이드

### 시나리오 A: 엔터프라이즈 구현(자체 호스팅)

- **역할:** 비즈니스가 이 명세를 구현합니다.
- **요구 사항:**
  1. 자체 인프라에 `endpoint`를 배포합니다.
  1. 자체 데이터베이스에서 토큰과 PAN을 내부적으로 매핑합니다.
- **보안:** **매우 중요.** 카드 자격 증명의 경우 비즈니스는 엔드포인트에서 원본 PAN을 받으므로 반드시 PCI DSS를 준수해야 합니다(**MUST**). 다른 자격 증명 유형에는 유형별 컴플라이언스 요구 사항이 있습니다.

### 시나리오 B: PSP 구현(서드파티)

- **역할:** PSP가 이 명세를 구현합니다.
- **요구 사항:**
  1. 판매자에게 `endpoint` URL을 제공합니다.
  1. 판매자에게 `identity.access_token`(판매자 보안 식별자)을 발급합니다.
  1. `binding.identity`가 최종 결제 청구를 요청하는 판매자와 일치하는지 검증합니다.
- **보안:** 자격 증명 저장에 따르는 컴플라이언스 부담은 PSP가 집니다 (예: 카드는 PCI DSS).

## 보안 고려 사항

| 요구 사항        | 설명                                                                                                                                                                |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **TLS/HTTPS**    | `config.endpoint`로 가는 모든 트래픽은 반드시 암호화해야 합니다(**MUST**).                                                                                          |
| **컴플라이언스** | `config.endpoint`를 호스팅하는 주체는 반드시 자격 증명 유형에 해당하는 데이터 표준(예: 카드는 PCI DSS, 개인 식별 정보는 GDPR 등)을 준수해야 합니다(**MUST**).       |
| **범위 격리**    | 플랫폼의 주 애플리케이션은 원본 자격 증명을 보아서는 안 됩니다(**MUST NOT**). 원본 자격 증명은 플랫폼의 보안 자격 증명 제공자와 토크나이저 호스트만 볼 수 있습니다. |
| **바인딩 검증**  | 토크나이저/프로세서는 반드시 최종 결제 시 제출된 `checkout_id`가 토큰화 시 제공된 `checkout_id`와 일치하는지 검증해야 합니다(**MUST**).                             |
