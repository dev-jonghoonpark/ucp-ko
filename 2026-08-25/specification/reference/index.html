    스키마 레퍼런스¶

    이 페이지에서는 UCP에서 사용하는 모든 기능 데이터 모델과 타입의 레퍼런스를 제공합니다.

    기능 스키마¶

    Location Lookup¶

    식별자로 위치를 조회합니다. 일괄 조회와 단일 위치 상세 조회를 지원합니다.

    Location Search¶

    위치 검색 기능. 자연어 검색어, 거리·서비스 가능 범위 관계, 현재 상품 가용성을 포함한 구조화된 필터링, 페이지네이션을 지원합니다.

    Cart¶

    이름 타입 필수 여부 설명
    ucp any 필수; 요청에서는 생략 장바구니 응답용 UCP 메타데이터. 체크아웃 전에는 결제 핸들러가 필요 없습니다.
    id string 필수; 요청에서는 생략 고유 장바구니 식별자.
    line_items Array[Line Item] 필수 장바구니 라인 아이템. 체크아웃과 구조가 같습니다. 업데이트 시 전체를 교체합니다.
    context Context 선택 현지화를 위한 구매자 신호(country, region, postal_code). 판매자는 이를 가격, 재고, 통화를 정하는 데 사용합니다. 생략하면 geo-IP로 대체합니다.
    signals Signals 선택 승인과 악용 방지를 돕기 위해 플랫폼이 제공하는 환경 데이터. 값은 구매자가 주장한 내용이어서는 안 됩니다(MUST NOT). 플랫폼은 직접 관찰했거나 독립적으로 검증 가능한 제3자 증명에 근거한 신호를 제공합니다. 여러 확장이 공유 네임스페이스에 값을 추가할 때 출처를 보장하고 충돌을 막기 위해, 모든 신호 키는 반드시 역도메인 이름을 사용해야 합니다(MUST).
    attribution Attribution 선택 플랫폼이 내보내는 추천 및 전환 이벤트 맥락: 캠페인 식별자, 클릭 ID, source/medium 마커 등. 브라우저 기반 흐름에서 플랫폼이 URL 쿼리 매개변수로 전달하는 것과 같은 매개변수입니다.
    buyer Buyer 선택 개인화된 견적을 위한 구매자 정보(선택 사항).
    currency string 필수; 요청에서는 생략 ISO 4217 통화 코드. 판매자가 컨텍스트나 geo-IP를 바탕으로 결정합니다.
    totals Totals 필수; 요청에서는 생략 예상 비용 내역. 배송비·세금을 아직 계산할 수 없으면 일부만 포함될 수 있습니다.
    actions Actions 선택; 요청에서는 생략 이 장바구니에 대해 확장이 정의한 미해결 Action.
    messages Array[Message] 선택; 요청에서는 생략 검증 메시지, 경고 또는 안내성 알림.
    links Array[Link] 선택; 요청에서는 생략 판매자 링크(선택 사항, 정책, FAQ).
    policies Array[Policy] 선택; 요청에서는 생략 이 장바구니의 항목에 적용되는 정책(예: 반품/환불 조건). applies_to 대상은 응답 루트를 기준으로 하며, 없거나 비어 있으면 links[]의 URL을 참조합니다.
    continue_url string 선택; 요청에서는 생략 장바구니 핸드오프와 세션 복구용 URL. 공유와 사람이 개입하는(human-in-the-loop) 흐름을 지원합니다.
    expires_at string 선택; 요청에서는 생략 장바구니 만료 타임스탬프(RFC 3339). 선택 사항.

    Catalog Lookup¶

    식별자로 상품·변형을 조회합니다. 일괄 조회(lookup_catalog)와 단일 상품 상세 조회(get_product)를 지원합니다.

    Catalog Search¶

    상품 카탈로그 검색 기능.

    Checkout¶

    이름 타입 필수 여부 설명
    ucp any 필수; 요청에서는 생략 체크아웃 응답용 UCP 메타데이터.
    id string 필수; 요청에서는 생략 체크아웃 세션의 고유 식별자.
    line_items Array[Line Item] 필수; complete 시 생략 체크아웃 중인 라인 아이템 목록.
    buyer Buyer 선택; complete 시 생략 구매자 정보.
    context Context 선택; complete 시 생략 관련성 판단과 현지화를 위한 잠정적 구매자 신호로, 권위 있는 데이터가 아닙니다. 검증된 입력(예: 배송 주소)이 없으면 비즈니스는 이 값을 사용해야 하며(SHOULD), 더 신뢰도 높은 신호(인증된 계정, 위험 탐지)나 규제 제약(수출 통제)과 맞지 않으면 무시하거나 우선순위를 낮출 수 있습니다(MAY). 자격 판단과 정책 적용은 반드시 체크아웃 시점에 구속력 있는 거래 데이터로 수행해야 합니다(MUST). 컨텍스트는 개인을 식별할 수 없어야 하며(SHOULD), 단계적으로 공개할 수 있습니다. 초기에는 대략적인 신호를, 세션이 진행되면서 더 세밀한 정보를 제공합니다. 더 세밀한 데이터(배송 주소, 청구 주소)가 컨텍스트보다 우선합니다.
    signals Signals 선택 승인과 악용 방지를 돕기 위해 플랫폼이 제공하는 환경 데이터. 값은 구매자가 주장한 내용이어서는 안 됩니다(MUST NOT). 플랫폼은 직접 관찰했거나 독립적으로 검증 가능한 제3자 증명에 근거한 신호를 제공합니다. 여러 확장이 공유 네임스페이스에 값을 추가할 때 출처를 보장하고 충돌을 막기 위해, 모든 신호 키는 반드시 역도메인 이름을 사용해야 합니다(MUST).
    attribution Attribution 선택 플랫폼이 내보내는 추천 및 전환 이벤트 맥락: 캠페인 식별자, 클릭 ID, source/medium 마커 등. 브라우저 기반 흐름에서 플랫폼이 URL 쿼리 매개변수로 전달하는 것과 같은 매개변수입니다.
    status string 필수; 요청에서는 생략 현재 단계와 필요한 처리를 나타내는 체크아웃 상태. 상태 전이에 대한 자세한 내용은 체크아웃 상태 수명 주기 문서를 참고하세요.
    허용 값: incomplete, requires_escalation, ready_for_complete, complete_in_progress, completed, canceled
    currency string 필수; 요청에서는 생략 판매자가 판단한 시장을 반영하는 ISO 4217 통화 코드. 주소, 컨텍스트, geo IP로 결정합니다. 구매자는 신호를 제공하고 통화는 판매자가 결정합니다.
    totals Totals 필수; 요청에서는 생략 장바구니의 각종 합계.
    actions Actions 선택; 요청에서는 생략 이 체크아웃에 대해 확장이 정의한 미해결 Action.
    messages Array[Message] 선택; 요청에서는 생략 체크아웃 세션 상태에 대한 오류·정보 메시지 목록.
    links Array[Link] 필수; 요청에서는 생략 플랫폼이 표시할 링크(개인정보처리방침, 이용약관). 법적 준수를 위해 필수입니다.
    policies Array[Policy] 선택; 요청에서는 생략 이 체크아웃의 항목에 적용되는 정책(예: 반품/환불 조건). applies_to 대상은 응답 루트를 기준으로 하며, 없거나 비어 있으면 links[]의 URL을 참조합니다.
    expires_at string 선택; 요청에서는 생략 RFC 3339 만료 타임스탬프입니다. 보내지 않으면 기본 TTL은 생성 시점부터 6시간입니다.
    continue_url string 선택; 요청에서는 생략 체크아웃 핸드오프와 세션 복구용 URL. status가 requires_escalation이면 반드시 제공해야 합니다(MUST). 형식과 가용성 요구 사항은 명세를 참고하세요.
    payment Payment 선택; complete 시 필수 핸들러를 포함한 결제 구성.
    order Order Confirmation 선택; 요청에서는 생략 이 체크아웃 세션으로 생성된 주문의 세부 정보.

    policies Array[Policy] 선택; 요청에서는 생략 체크아웃 시 항목에 적용된 정책의 스냅샷으로, 지속적인 기록으로 주문에 저장됩니다. applies_to 대상은 응답 루트를 기준으로 합니다.
    messages Array[Message] 선택 비즈니스 결과 메시지(오류, 경고, 정보). 비즈니스가 플랫폼에 상태나 문제를 전달해야 할 때 포함됩니다.
    attribution Attribution 선택; 요청에서는 생략 원래 체크아웃과 연결된 어트리뷰션의 스냅샷입니다. 주문에서는 읽기 전용입니다.

    Actions¶

    확장이 정의한 미해결 Action 인스턴스. 키는 확장 이름이 아니라 역 도메인 형식의 Action 유형입니다.

    Amenity Type¶

    이름 타입 필수 여부 설명
    기능, 서비스, 핸들러, 자격 클레임, 확장이 추가한 키에 충돌 없는 네임스페이스를 부여하는 역도메인 식별자입니다. 점으로 구분된 세그먼트가 두 개 이상 있어야 합니다(예: 'dev.ucp.shopping.checkout', 'com.example.loyalty_gold'). 첫 번째 이후의 세그먼트는 도메인이나 식별자에서 파생되므로 중간에 하이픈을 포함하거나 숫자로 시작하거나 밑줄을 포함할 수 있지만(예: 'com.example-shop.checkout', 'com.2example.cart', 'dev.ucp.common.identity_linking'), 하이픈으로 시작하거나 끝나서는 안 됩니다. 첫 번째 세그먼트(뒤집힌 최상위 도메인)는 문자와 숫자로 이루어지며, 'xn--p1ai' 같은 국제화(punycode) 최상위 도메인을 지원하기 위해 중간에 하이픈을 포함할 수 있습니다.

    패턴: ^[a-z](?:[a-z0-9-]*[a-z0-9])?(?:\.[a-z0-9](?:[a-z0-9_-]*[a-z0-9_])?)+$

    Amount¶

    ISO 4217에 정의된 통화의 최소 단위로 나타낸 금액. 최소 단위와 기본 단위의 비율은 통화의 지수를 참고합니다(예: USD는 2, JPY는 0, KWD는 3).

    Card Payment Instrument¶

    이름 타입 필수 여부 설명
    id string 필수 이 결제 수단 인스턴스의 고유 식별자. 플랫폼이 수집하는 결제 수단은 보통 플랫폼이 할당합니다. 신원 연결된 응답으로 반환되는, 비즈니스가 소유한 저장 결제 수단이라면 비즈니스가 이 식별자를 할당합니다. 플랫폼은 반드시 이를 불투명한 비즈니스 범위 참조로 취급해야 하며(MUST), 구매자가 선택하면 비즈니스가 서버 측에서 해석합니다.
    handler_id string 필수 이 결제 수단을 생성한 핸들러 인스턴스의 고유 식별자. 결제 핸들러 정의의 'id' 필드에 해당합니다.
    type string 필수 결제 수단의 대분류(예: 'card', 'tokenized_card'). 구체적인 스키마에서 이 값을 상수로 제한합니다.
    billing_address Postal Address 선택 이 결제 방법에 연결된 청구지 주소.
    credential Payment Credential 선택 모든 결제 자격 증명의 기본 정의. 구체적인 자격 증명 유형은 핸들러가 정의합니다.
    display object 선택 이 결제 수단의 표시 정보. 각 결제 수단 스키마가 결제 핸들러의 설명에 따라 고유한 표시 속성을 정의합니다.
    type string 필수 상수 = card. 카드 결제 수단임을 나타냅니다.
    network string 선택 이 거래에 선택된 카드 네트워크로, 보통 공동 브랜드(co-badged) 카드에서 선택한 네트워크입니다. 이 값이 있을 때 카드를 해당 네트워크로 라우팅할 수 없으면 비즈니스는 거절할 수 있으며(MAY), 다른 네트워크로 대체해서는 안 됩니다(MUST NOT).
    display object 선택 이 카드 결제 수단의 표시 정보.

    Constraint Expression¶

    이름 타입 필수 여부 설명
    required Array[string] 선택 제약 대상 객체에 반드시 있어야 하는 속성 이름입니다. 비어 있으면 안 됩니다. 빈 배열은 아무 제약도 적용하지 않습니다.
    properties object 선택 속성 이름을 키로 하는 제약 조건. 비어 있으면 안 됩니다. 빈 객체는 아무 제약도 적용하지 않습니다.
    anyOf Array[Constraint Expression] 선택 대안 객체 제약. 제약 대상 객체는 최소 하나를 만족해야 합니다. 분기는 비어 있으면 안 됩니다. 빈 분기는 모든 객체가 만족하므로 대안 구성을 무력화합니다.

    Context¶

    이름 타입 필수 여부 설명
    address_country string 선택 2자리 ISO 3166-1 alpha-2 코드로 표기한 국가(예: "US"). 3자리 alpha-3 코드나 전체 국가명을 사용할 수도 있습니다(MAY).
    address_region string 선택 국가 안의 1차 행정 구역(예: California 같은 주 또는 도).
    postal_code string 선택 우편번호(예: "94043").
    location string 선택 비즈니스 네임스페이스 안에서 위치(Location)를 가리키는 안정적이고 불투명한 식별자. 이 값은 잠정적이고 구속력 없는 힌트이며 구매자의 지역 정보와는 별개입니다. 효과는 작업 명세나 활성화된 기능/확장이 정의합니다. 소매 쇼핑의 흔한 예로, 사용자가 식료품을 구매할 때 선택해 저장한 기본 단골 매장 ID가 있습니다.
    intent string 선택 구매자의 의도를 설명하는 배경 맥락(예: 'looking for a gift under $50', 'need something durable for outdoor use'). 관련성, 추천, 개인화에 활용됩니다.
    language string 선택 콘텐츠의 선호 언어입니다. IETF BCP 47 언어 태그(예: 'en', 'fr-CA', 'zh-Hans')를 사용합니다. REST에서는 Accept-Language 헤더에 해당합니다. 이 필드가 없으면 플랫폼은 Accept-Language로 대체해야 하며(SHOULD), 값이 있으면 Accept-Language보다 우선합니다. 해당 언어를 제공할 수 없으면 비즈니스는 다른 언어로 콘텐츠를 반환할 수 있습니다(MAY).
    currency string 선택 선호 통화(ISO 4217, 예: 'EUR', 'USD'). 비즈니스는 맥락과 신뢰할 수 있는 신호로 표시 통화를 결정하며, 다중 통화 시장에서는 이 힌트를 선택에 참고할 수 있습니다(MAY). 가격 필터 값의 통화 단위로도 쓰이므로, 플랫폼은 가격 필터를 보낼 때 이 필드를 포함해야 합니다(SHOULD). 응답 가격에는 결정된 통화를 확인할 수 있도록 통화가 명시됩니다.
    eligibility Array[Reverse Domain Name] 선택 로열티 멤버십, 결제 수단 혜택 등 적격 혜택에 대한 구매자 주장. 인식된 주장은 비즈니스 응답에 반영될 수 있습니다(MAY)(예: 회원 전용 상품 구매 가능 여부, 카탈로그의 조정 가격, 장바구니나 체크아웃의 잠정 할인). 비즈니스는 인식하지 못한 값을 오류 없이 반드시 무시해야 합니다(MUST). 값은 반드시 역 도메인 이름 규칙을 사용해야 하며(MUST)(예: 'com.example.loyalty_gold', 'org.school.student'), 반드시 개인을 식별할 수 없어야 합니다(MUST).
    payment Array[object] 선택 구매자가 선호하는 결제 핸들러를 우선순위 순서(가장 선호하는 것이 먼저)로 나열합니다. 각 항목은 비즈니스 프로필의 ucp.payment_handlers에 공개된 핸들러를 가리키며, 선호하는 결제 수단 유형으로 범위를 좁힐 수도 있습니다. 비즈니스는 이를 사용해 핸들러(유형이 주어지면 유형까지)를 미리 선택하거나 우선순위를 정해야 하며(SHOULD), 사용할 수 없거나 자격이 없는 항목은 무시할 수 있습니다(MAY). 인식하지 못하는 값은 오류 없이 반드시 무시해야 합니다(MUST).

    Measure¶

    이름 타입 필수 여부 설명
    unit string 필수 안정적인 기계 식별자. 단위를 정확히 식별하는 UN/CEFACT Rec20 Common Code가 있으면 비즈니스는 그 코드를 그대로 사용해야 합니다(SHOULD). 그렇지 않으면 비즈니스는 사용자 정의 단위 식별자를 사용할 수 있으며(MAY), 같은 단위에는 반드시 일관되게 사용해야 합니다(MUST). 플랫폼은 반드시 인식하지 못한 식별자를 불투명한 값으로 취급해야 합니다(MUST).
    scale integer 선택 한 스텝은 unit의 10^-scale입니다. unit이 C62이면 scale은 있을 경우 반드시 0이어야 합니다(MUST). 최댓값 15는 상호 운용 가능한 정수 범위에서 도출됩니다. scale이 16이면 기본 단위 하나(10^16 스텝)를 더 이상 표현할 수 없으므로, 그보다 큰 scale로는 자기 기준 단위 하나를 나타낼 수 없습니다. 더 세밀한 단위가 필요한 비즈니스는 더 작은 unit을 사용합니다.
    display_text string 필수 비즈니스가 제공하는 필수 출력용 단위 레이블입니다. 플랫폼이 unit을 인식하지 못하면 반드시 이 레이블을 사용해야 하며(MUST), 인식하는 UN/CEFACT Rec 20 Common Code라면 자체 현지화 레이블로 대체할 수 있습니다(MAY). 이 값은 단위 식별이나 불일치 비교에 관여하지 않습니다.
    value integer 필수 unit의 10^-scale 단위 개수(정수).

    id string 필수 이 결제 수단 인스턴스의 고유 식별자. 플랫폼이 수집하는 결제 수단은 보통 플랫폼이 할당합니다. 신원 연결된 응답으로 반환되는, 비즈니스가 소유한 저장 결제 수단이라면 비즈니스가 이 식별자를 할당합니다. 플랫폼은 반드시 이를 불투명한 비즈니스 범위 참조로 취급해야 하며(MUST), 구매자가 선택하면 비즈니스가 서버 측에서 해석합니다.
    handler_id string 필수 이 결제 수단을 생성한 핸들러 인스턴스의 고유 식별자. 결제 핸들러 정의의 'id' 필드에 해당합니다.
    type string 필수 결제 수단의 대분류(예: 'card', 'tokenized_card'). 구체적인 스키마에서 이 값을 상수로 제한합니다.
    billing_address Postal Address 선택 이 결제 방법에 연결된 청구지 주소.
    credential Payment Credential 선택 모든 결제 자격 증명의 기본 정의. 구체적인 자격 증명 유형은 핸들러가 정의합니다.
    display object 선택 이 결제 수단의 표시 정보. 각 결제 수단 스키마가 결제 핸들러의 설명에 따라 고유한 표시 속성을 정의합니다.

    Payment Schedule¶

    이름 타입 필수 여부 설명
    id string 필수 이 결제 일정의 식별자로, 해당 결제 조건 안에서 고유합니다. 일정이 같은 결제를 나타내는 동안 비즈니스는 응답 간에 이 값을 안정적으로 유지해야 합니다(SHOULD).
    type string 필수 개방형 어휘에서 가져온 시점 분류. 정의된 의미가 있는 값은 immediate뿐이며, 체크아웃이 완료되는 시점에 결제해야 함을 뜻합니다. 그 밖의 값은 완료 시점에 결제할 필요가 없음을 뜻하고, 결제 시기는 description에 기술합니다. 결제 시점에 승인, 매입, 정산 중 무엇이 일어나는지는 결제 핸들러의 동작이며 이 확장의 범위를 벗어납니다. 비즈니스는 추가 값(예: deferred, on_shipment)을 사용할 수 있으며(MAY), 플랫폼은 반드시 인식하지 못한 값을 완료 시점에 결제할 필요가 없는 것으로 취급해야 합니다(MUST).
    description Description 필수 이 결제가 언제, 어떻게 이루어져야 하는지를 구매자에게 완전하게 설명하는 문구. 비즈니스는 반드시 이 필드만으로 충분하게 만들어야 합니다(MUST). 즉, type 값을 하나도 인식하지 못하고 다른 필드를 전혀 읽지 않는 플랫폼도 반드시 이 일정을 올바르게 표시할 수 있어야 합니다(MUST). 플랫폼은 더 나은 표시를 위해 type과 due_at을 사용할 수 있지만(MAY), 이 필드와 모순되는 파생 시점을 표시해서는 안 됩니다(MUST NOT).
    due_at string 선택 비즈니스가 체크아웃 시점에 결정할 수 있을 때, 이 결제의 만기를 나타내는 절대 RFC 3339 date-time. description을 보완할 뿐 대체하지 않습니다. 만기일이 향후 이벤트에 따라 달라지면(예: 'due on delivery') 생략하며, 이때 시점은 description에만 명시합니다.
    amount Amount 필수 이 결제가 이루어질 때 청구되는 금액으로, 세금과 기타 모든 요금을 포함하며 체크아웃 통화의 최소 단위(ISO 4217)로 표시합니다. 일정은 합계 내역이 아니라 금액을 명시합니다. 구매 가격은 체크아웃에서 한 번 정해지고, 일정은 그 가격의 일부 또는 전부를 옮길 뿐입니다. 선택한 조건 때문에 구매 비용이 달라지면 그 차이는 여기가 아니라 checkout.totals에 나타납니다.

    Payment Term¶

    이름 타입 필수 여부 설명
    id string 필수 체크아웃 안에서 이 결제 조건의 고유 식별자. payment.selected_term_id가 참조합니다.
    title string 필수 형제 조건과 이 조건을 구분하는 짧은 레이블(예: 'Pay now', 'Pay in 4', 'Deposit + balance at check-in').
    description Description 선택 제목을 보충하는 맥락 정보(예: 'Save 5% by paying today'). 그대로 렌더링할 수 있으며, 제목을 반복해서는 안 됩니다(MUST NOT).
    schedules Array[Payment Schedule] 필수 이 조건에 따라 이 체크아웃을 정산하는 결제 일정. 납부 기한 순서로 나열합니다.

    Policy¶

    이름 타입 필수 여부 설명
    type Reverse Domain Name 필수 정책 유형 판별자. 열린 역 DNS 어휘입니다. 잘 알려진 값: dev.ucp.shopping.policy.return(반품 조건), dev.ucp.shopping.policy.warranty(보증 조건). 비즈니스는 자체 도메인에 사용자 정의 유형을 정의할 수 있습니다(MAY, 예: com.example.policy.price_match). 플랫폼은 알 수 없는 값을 반드시 허용해야 합니다(MUST).
    description Description 필수 하나 이상의 형식(plain, markdown, html)으로 된 사람이 읽을 수 있는 정책 요약. 플랫폼이 유형별 필드를 이해하지 못해도 표시할 수 있도록 모든 정책에 필수입니다. 이것은 구매자 대상 고지가 아닙니다. 표시 의무는 messages[] 경고로 부과됩니다(정책 섹션 참고).
    applies_to Array[string] 선택 이 정책이 적용되는 노드를 가리키는 RFC 9535 JSONPath 표현식으로, 응답을 포함하는 루트를 기준으로 합니다(예: 장바구니·체크아웃의 $.line_items[0], 카탈로그의 $.products[2]). 각 대상은 지정한 노드와 그 아래에 중첩된 모든 것을 포함하므로, 상품을 대상으로 하면 그 변형도 포함됩니다. 단수 쿼리(RFC 9535 Section 2.3.5.1, 이름·인덱스 선택자만 사용)는 노드 하나를 지정하고, 필터·와일드카드·슬라이스는 노드 집합과 일치합니다. 생략하면 정책이 응답 전체에 적용됩니다. 같은 type의 정책들이 한 노드를 두고 경합하면 가장 좁은 대상이 이기고 나머지를 덮어씁니다. 구체성을 판정하는 방법은 정책 섹션을 참고하세요.
    url string 선택 전체 정책 문서 링크(선택 사항).

    Quantity Unit¶

    이름 타입 필수 여부 설명
    unit string 필수 안정적인 기계 식별자. 단위를 정확히 식별하는 UN/CEFACT Rec20 Common Code가 있으면 비즈니스는 그 코드를 그대로 사용해야 합니다(SHOULD). 그렇지 않으면 비즈니스는 사용자 정의 단위 식별자를 사용할 수 있으며(MAY), 같은 단위에는 반드시 일관되게 사용해야 합니다(MUST). 플랫폼은 반드시 인식하지 못한 식별자를 불투명한 값으로 취급해야 합니다(MUST).
    scale integer 선택 한 스텝은 unit의 10^-scale입니다. unit이 C62이면 scale은 있을 경우 반드시 0이어야 합니다(MUST). 최댓값 15는 상호 운용 가능한 정수 범위에서 도출됩니다. scale이 16이면 기본 단위 하나(10^16 스텝)를 더 이상 표현할 수 없으므로, 그보다 큰 scale로는 자기 기준 단위 하나를 나타낼 수 없습니다. 더 세밀한 단위가 필요한 비즈니스는 더 작은 unit을 사용합니다.
    display_text string 필수 비즈니스가 제공하는 필수 출력용 단위 레이블입니다. 플랫폼이 unit을 인식하지 못하면 반드시 이 레이블을 사용해야 하며(MUST), 인식하는 UN/CEFACT Rec 20 Common Code라면 자체 현지화 레이블로 대체할 수 있습니다(MAY). 이 값은 단위 식별이나 불일치 비교에 관여하지 않습니다.
    increment integer 선택 스텝 단위로 나타낸 주문 단위: 비즈니스는 이 항목을 increment 스텝의 정수배로 판매합니다. 실제 적용 값은 제공된 값이며, 없으면 1입니다. 이는 표현 범위의 제한이 아니라 권고 성격의 판매 정책입니다. 플랫폼이 작성한 수량은 실제 적용 increment의 정수배여야 합니다(SHOULD). 비즈니스는 increment에 맞지 않는 요청을 수락하거나, 수정하거나, 복구 가능한 비즈니스 결과와 함께 거부할 수 있으며(MAY), 이를 임의로 재해석해서는 안 됩니다(MUST NOT). 비즈니스가 작성한 수량(체크아웃 수정, 풀필먼트 이벤트, 조정)은 scale의 제약만 받습니다.

    Request Constraints¶

    이름 타입 필수 여부 설명
    path string 선택 같은 리소스에 대한 다음 논리적 UCP 요청을 대상으로 평가되는 완전한 RFC 9535 JSONPath 쿼리.
    required Array[string] 선택 제약 대상 객체에 반드시 있어야 하는 속성 이름입니다. 비어 있으면 안 됩니다. 빈 배열은 아무 제약도 적용하지 않습니다.
    properties object 선택 속성 이름을 키로 하는 제약 조건. 비어 있으면 안 됩니다. 빈 객체는 아무 제약도 적용하지 않습니다.
    anyOf Array[Constraint Expression] 선택 대안 객체 제약. 제약 대상 객체는 최소 하나를 만족해야 합니다. 분기는 비어 있으면 안 됩니다. 빈 분기는 모든 객체가 만족하므로 대안 구성을 무력화합니다.

    Reverse Domain Name¶

    기능, 서비스, 핸들러, 자격 클레임, 확장이 추가한 키에 충돌 없는 네임스페이스를 부여하는 역도메인 식별자입니다. 점으로 구분된 세그먼트가 두 개 이상 있어야 합니다(예: 'dev.ucp.shopping.checkout', 'com.example.loyalty_gold'). 첫 번째 이후의 세그먼트는 도메인이나 식별자에서 파생되므로 중간에 하이픈을 포함하거나 숫자로 시작하거나 밑줄을 포함할 수 있지만(예: 'com.example-shop.checkout', 'com.2example.cart', 'dev.ucp.common.identity_linking'), 하이픈으로 시작하거나 끝나서는 안 됩니다. 첫 번째 세그먼트(뒤집힌 최상위 도메인)는 문자와 숫자로 이루어지며, 'xn--p1ai' 같은 국제화(punycode) 최상위 도메인을 지원하기 위해 중간에 하이픈을 포함할 수 있습니다.

    패턴: ^[a-z](?:[a-z0-9-]*[a-z0-9])?(?:\.[a-z0-9](?:[a-z0-9_-]*[a-z0-9_])?)+$

    Unit¶

    이름 타입 필수 여부 설명
    unit string 필수 안정적인 기계 식별자. 단위를 정확히 식별하는 UN/CEFACT Rec20 Common Code가 있으면 비즈니스는 그 코드를 그대로 사용해야 합니다(SHOULD). 그렇지 않으면 비즈니스는 사용자 정의 단위 식별자를 사용할 수 있으며(MAY), 같은 단위에는 반드시 일관되게 사용해야 합니다(MUST). 플랫폼은 반드시 인식하지 못한 식별자를 불투명한 값으로 취급해야 합니다(MUST).
    scale integer 선택 한 스텝은 unit의 10^-scale입니다. unit이 C62이면 scale은 있을 경우 반드시 0이어야 합니다(MUST). 최댓값 15는 상호 운용 가능한 정수 범위에서 도출됩니다. scale이 16이면 기본 단위 하나(10^16 스텝)를 더 이상 표현할 수 없으므로, 그보다 큰 scale로는 자기 기준 단위 하나를 나타낼 수 없습니다. 더 세밀한 단위가 필요한 비즈니스는 더 작은 unit을 사용합니다.
    display_text string 필수 비즈니스가 제공하는 필수 출력용 단위 레이블입니다. 플랫폼이 unit을 인식하지 못하면 반드시 이 레이블을 사용해야 하며(MUST), 인식하는 UN/CEFACT Rec 20 Common Code라면 자체 현지화 레이블로 대체할 수 있습니다(MAY). 이 값은 단위 식별이나 불일치 비교에 관여하지 않습니다.

    Item¶

    이름 타입 필수 여부 설명
    id string 필수 이 라인 아이템에 연결된 상품 세부 정보를 확인하는 데 필요한 상품 식별자로, 주로 SKU입니다. 플랫폼과 비즈니스 모두 인식할 수 있어야 합니다.
    title string 필수; 요청에서는 생략 상품 제목.
    price Amount 필수; 요청에서는 생략 ISO 4217 최소 단위로 표시한 단가. 가격은 quantity_unit.unit 하나(예: lb당 또는 시간당)에 대한 금액이며, quantity_unit이 없으면 each 기준입니다.
    quantity_unit Quantity Unit 선택 이 항목의 quantity가 표시되는 판매 기준입니다. 권위 있는 비즈니스 응답에서 이 값이 없으면 기본값인 each의 기계적 정체성(C62, 0)을 뜻하며, each가 아닌 모든 응답에는 비즈니스가 반드시 이 기술자를 포함해야 합니다(MUST). 플랫폼 요청에서는 생략해도 아무것도 주장하지 않으며, 비즈니스는 항목의 권위 있는 판매 기준으로 quantity를 해석합니다. 플랫폼이 이 기술자를 포함하면 단위 기술자의 기계적 정체성을 주장하는 것입니다. 비즈니스는 반드시 그 기계적 정체성(unit, 실효 scale)을 비교하고(MUST), display_text와 increment는 무시하며, 불일치는 경고와 함께 눈에 보이는 라인 수정으로 드러나는 변환이나 복구 가능한 비즈니스 결과로 거부하는 방식으로 해결해야 합니다. 조용히 다르게 해석하는 것은 금지됩니다. 실효 scale 0의 명시적 C62 기술자는 기술자가 없는 것으로 표현된 권위 있는 판매 기준과 일치합니다.
    unit_price Unit Price 선택; 요청에서는 생략 이 항목의 가격 책정 기준입니다. 권위 있는 비즈니스 응답에서는 가격 책정 기준이 판매 기준과 다른 모든 라인(예: 파운드당 가격이지만 each 단위로 판매)에 비즈니스가 반드시 unit_price를 포함해야 합니다(MUST). 라인에 이 값이 있으면 해당 단가는 표시용이 아니라 거래에 쓰이는 값입니다. 가격 책정 기준이 판매 기준과 같으면 item.price만으로 청구 금액이 온전히 정해지므로 이 필드는 생략할 수 있습니다(MAY).
    image_url string 선택; 요청에서는 생략 상품 이미지 URI.

    Unit Price¶

    이름 타입 필수 여부 설명
    amount Amount 필수 ISO 4217 최소 단위로 표시한 단가. 동일 단위 불변 조건을 충족한 뒤, 비즈니스는 반드시 비교 단가를 (price.amount / (measure.value × 10^-measure.scale)) × (reference.value × 10^-reference.scale)로 계산하고 자체 가격 규칙에 따라 ISO 4217 최소 단위로 한 번 반올림해야 합니다(MUST). 반환된 unit_price.amount가 권위 있는 값이며, 플랫폼은 이를 다시 계산하거나 자체 결과로 대체해서는 안 됩니다(MUST NOT).
    currency string 필수 ISO 4217 통화 코드.
    measure any 필수 포장·내용물 기준의 상품 용량(예: 750 mL 병)으로, 판매 기준을 정의하는 quantity_unit과는 다릅니다. 정수 value는 반드시 1 이상이어야 합니다(MUST).
    reference any 필수 단위 가격 표시의 기준 단위(예: 100 mL당, 1 kg당). 정수 value는 반드시 1 이상이어야 합니다(MUST).

    quantity_unit Quantity Unit 선택 이 변형의 quantity가 표시되는 판매 기준입니다. 기본 판매 기준은 each이며, 기계적 정체성은 (C62, 0)입니다. C62는 one/each를 뜻하는 UN/CEFACT Rec20 코드입니다. 카탈로그 기술자가 없으면 이 기본값을 뜻합니다. increment는 스텝 단위의 주문 단위를 알립니다(예: scale 2에 increment 25이면 0.25 단위의 배수로 판매).

    unit_price Unit Price 선택 선반 표시 방식의 가격 비교에 쓰는 표준 측정 단위당 가격입니다. 단위 가격이 적용되지 않으면 생략할 수 있습니다(MAY).

    연결된 리워드 통화의 최소 단위로 나타낸 음이 아닌 정수 금액. 최소 단위와 기본 단위의 비율은 연결된 리워드 통화의 decimal_places가 정의하며, 생략하면 기본값은 0입니다.

    Earning Breakdown¶

    리워드 적립 내역 규칙

    이름 타입 필수 여부 설명
    id string 필수 고유 리워드 내역 규칙 식별자.
    amount integer 필수 이 규칙으로 적립된 리워드.
    description string 필수 특정 리워드에 대해 바로 표시할 수 있는, 사람이 읽을 수 있는 근거(예: 신발 2배 적립).
    benefit_id string 선택 이 리워드 규칙을 만든 membership_tier_benefit의 id(선택 사항). 같은 상위 로열티 멤버십 안의 membership_tier_benefit.id로 해석됩니다.

    Loyalty Membership¶

    상위 맵 키가 나타내는 자격 조건 클레임에 대해 비즈니스가 수락한 로열티 멤버십. 독립적으로 가입할 수 있는 프로그램은 반드시 로열티 맵 아래에 별도의 형제 항목으로 모델링하고, 역 도메인 명명(예: 'com.example.rewards'와 'com.example.rewards.card')으로 구분해야 합니다(MUST).

    이름 타입 필수 여부 설명
    id string 필수 고유 로열티 멤버십 식별자.
    name string 필수 로열티 멤버십/프로그램의 비즈니스별 이름.
    display_id string 선택 사용자가 알아볼 수 있도록 마스킹되거나 일부만 표시한 멤버십 ID(예: '****5678'). 멤버십이 검증되지 않았다면 설정해서는 안 됩니다(MUST NOT).
    tiers Array[object] 선택 이 멤버십의 활성 또는 표시해도 안전한 등급 정보. 대부분의 프로그램은 단일 등급(항목 하나)이며, 병렬 등급 차원(예: 현재 등급과 평생 등급)이 있는 프로그램은 활성 등급마다 항목을 하나씩 채웁니다. 등급 정보가 확정되지 않았으면 생략합니다.
    rewards Array[object] 선택 이 멤버십과 연결된 리워드 유형과 적립 예측입니다. 각 객체는 리워드 유형 하나를 담습니다.
    provisional boolean 필수 이 멤버십에 추가 검증이 필요하면 true.

    Loyalty¶

    Payment AP2 Mandate Extension¶

    Merchant Authorization¶

    체크아웃 응답 본문(ap2 필드 제외)에 대한 JWS Detached Content 서명(RFC 7515 Appendix F). 형식: <base64url-header>..<base64url-signature>. 헤더에는 반드시 'alg'(ES256/ES384/ES512)와 'kid' 클레임이 있어야 합니다(MUST). 서명은 헤더와 JCS로 정규화한 체크아웃 페이로드를 모두 대상으로 합니다.

    패턴: ^[A-Za-z0-9_-]+\.\.[A-Za-z0-9_-]+$

    Checkout Mandate¶

    ap2.checkout_mandate에 담기는 SD-JWT+kb 자격 증명입니다. 사용자가 체크아웃을 승인했음을 증명합니다. ap2.merchant_authorization을 포함한 체크아웃 전체가 들어 있습니다.

    패턴: ^[A-Za-z0-9_-]+\.[A-Za-z0-9_-]*\.[A-Za-z0-9_-]+(~[A-Za-z0-9_-]+)*$

    Checkout with AP2 Mandate¶

    AP2 위임(Mandate) 지원이 추가된 체크아웃.

    이름 타입 필수 여부 설명
    ucp any 필수 체크아웃 응답용 UCP 메타데이터.
    id string 필수 체크아웃 세션의 고유 식별자.
    line_items Array[object] 필수 체크아웃 중인 라인 아이템 목록.
    buyer object 선택 구매자 정보.
    context object 선택 관련성 판단과 현지화를 위한 잠정적 구매자 신호로, 권위 있는 데이터가 아닙니다. 검증된 입력(예: 배송 주소)이 없으면 비즈니스는 이 값을 사용해야 하며(SHOULD), 더 신뢰도 높은 신호(인증된 계정, 위험 탐지)나 규제 제약(수출 통제)과 맞지 않으면 무시하거나 우선순위를 낮출 수 있습니다(MAY). 자격 판단과 정책 적용은 반드시 체크아웃 시점에 구속력 있는 거래 데이터로 수행해야 합니다(MUST). 컨텍스트는 개인을 식별할 수 없어야 하며(SHOULD), 단계적으로 공개할 수 있습니다. 초기에는 대략적인 신호를, 세션이 진행되면서 더 세밀한 정보를 제공합니다. 더 세밀한 데이터(배송 주소, 청구 주소)가 컨텍스트보다 우선합니다.
    signals object 선택 승인과 악용 방지를 돕기 위해 플랫폼이 제공하는 환경 데이터. 값은 구매자가 주장한 내용이어서는 안 됩니다(MUST NOT). 플랫폼은 직접 관찰했거나 독립적으로 검증 가능한 제3자 증명에 근거한 신호를 제공합니다. 여러 확장이 공유 네임스페이스에 값을 추가할 때 출처를 보장하고 충돌을 막기 위해, 모든 신호 키는 반드시 역도메인 이름을 사용해야 합니다(MUST).
    attribution object 선택 플랫폼이 내보내는 추천 및 전환 이벤트 맥락: 캠페인 식별자, 클릭 ID, source/medium 마커 등. 브라우저 기반 흐름에서 플랫폼이 URL 쿼리 매개변수로 전달하는 것과 같은 매개변수입니다.
    status string 필수 현재 단계와 필요한 처리를 나타내는 체크아웃 상태. 상태 전이에 대한 자세한 내용은 체크아웃 상태 수명 주기 문서를 참고하세요.
    허용 값: incomplete, requires_escalation, ready_for_complete, complete_in_progress, completed, canceled
    currency string 필수 판매자가 판단한 시장을 반영하는 ISO 4217 통화 코드. 주소, 컨텍스트, geo IP로 결정합니다. 구매자는 신호를 제공하고 통화는 판매자가 결정합니다.
    totals Array[Total] 필수 장바구니의 각종 합계.
    actions object 선택 이 체크아웃에 대해 확장이 정의한 미해결 Action.
    messages Array[object] 선택 체크아웃 세션 상태에 대한 오류·정보 메시지 목록.
    links Array[object] 필수 플랫폼이 표시할 링크(개인정보처리방침, 이용약관). 법적 준수를 위해 필수입니다.
    policies Array[object] 선택 이 체크아웃의 항목에 적용되는 정책(예: 반품/환불 조건). applies_to 대상은 응답 루트를 기준으로 하며, 없거나 비어 있으면 links[]의 URL을 참조합니다.
    expires_at string 선택 RFC 3339 만료 타임스탬프입니다. 보내지 않으면 기본 TTL은 생성 시점부터 6시간입니다.
    continue_url string 선택 체크아웃 핸드오프와 세션 복구용 URL. status가 requires_escalation이면 반드시 제공해야 합니다(MUST). 형식과 가용성 요구 사항은 명세를 참고하세요.
    payment object 선택 핸들러를 포함한 결제 구성.
    order object 선택 이 체크아웃 세션으로 생성된 주문의 세부 정보.
    ap2 any 선택

    Payment Split Payments Extension¶

    Instrument Group¶

    허용된 조합 안에서 이 그룹을 채울 수 있는 결제 수단 유형과 허용 개수를 정의하는 제약.

    이름 타입 필수 여부 설명
    types Array[string] 필수 이 그룹이 받는 결제 수단 유형(OR 논리). 나열된 유형 중 하나면 충족합니다.
    min integer 선택 이 그룹에서 필요한 최소 결제 수단 개수. 기본값은 0(선택 사항)입니다.
    max integer 선택 이 그룹에서 허용되는 최대 결제 수단 개수. 기본값은 1입니다. 반드시 min 이상이어야 합니다(MUST).

    Payment Instrument (Split Payments)¶

    분할 결제를 위해 결제 수단별 금액(선택 사항)으로 확장된 결제 수단.

    이름 타입 필수 여부 설명
    id string 필수 이 결제 수단 인스턴스의 고유 식별자. 플랫폼이 수집하는 결제 수단은 보통 플랫폼이 할당합니다. 신원 연결된 응답으로 반환되는, 비즈니스가 소유한 저장 결제 수단이라면 비즈니스가 이 식별자를 할당합니다. 플랫폼은 반드시 이를 불투명한 비즈니스 범위 참조로 취급해야 하며(MUST), 구매자가 선택하면 비즈니스가 서버 측에서 해석합니다.
    handler_id string 필수 이 결제 수단을 생성한 핸들러 인스턴스의 고유 식별자. 결제 핸들러 정의의 'id' 필드에 해당합니다.
    type string 필수 결제 수단의 대분류(예: 'card', 'tokenized_card'). 구체적인 스키마에서 이 값을 상수로 제한합니다.
    billing_address object 선택 이 결제 방법에 연결된 청구지 주소.
    credential object 선택 모든 결제 자격 증명의 기본 정의. 구체적인 자격 증명 유형은 핸들러가 정의합니다.
    display object 선택 이 결제 수단의 표시 정보. 각 결제 수단 스키마가 결제 핸들러의 설명에 따라 고유한 표시 속성을 정의합니다.
    amount integer 선택 이 결제 수단의 분담 금액으로, 이를 포함하는 기능 객체의 currency 기준 ISO 4217 최소 단위로 표현합니다. 요청 시: 플랫폼이 요청하는 분담 금액(금액을 정하지 않으면 생략). 응답 시: 실제로 승인되거나 청구된 금액(최종 처리되지 않았으면 생략).

    Payment Terms Extension¶

    Payment Term¶

    체크아웃 결제 방식: 함께 총액을 충당하는 하나 이상의 결제 일정.

    이름 타입 필수 여부 설명
    id string 필수 체크아웃 안에서 이 결제 조건의 고유 식별자. payment.selected_term_id가 참조합니다.
    title string 필수 형제 조건과 이 조건을 구분하는 짧은 레이블(예: 'Pay now', 'Pay in 4', 'Deposit + balance at check-in').
    description object 선택 제목을 보충하는 맥락 정보(예: 'Save 5% by paying today'). 그대로 렌더링할 수 있으며, 제목을 반복해서는 안 됩니다(MUST NOT).
    schedules Array[object] 필수 이 조건에 따라 이 체크아웃을 정산하는 결제 일정. 납부 기한 순서로 나열합니다.

    Payment with Terms¶

    선택 가능한 결제 조건으로 확장된 결제 객체.

    이름 타입 필수 여부 설명
    terms Array[object] 선택 구매자가 선택할 수 있는 결제 조건. 선택되지 않은 조건의 금액은 참고용이며, 선택된 조건의 일정 금액 합계는 체크아웃 총액과 같습니다.
    selected_term_id string 선택 선택한 결제 조건의 ID. 반드시 최신 체크아웃 응답의 terms[].id 중 하나와 일치해야 합니다(MUST). 응답에 terms가 있으면 항상 함께 있고, 없으면 함께 없습니다. 체크아웃 합계는 선택한 조건의 합계이므로, 선택 없이 조건 목록만 있으면 어떤 조건과도 맞지 않는 금액이 표시되기 때문입니다. 구매자가 선택하지 않았다면 비즈니스가 기본값을 선택합니다. 조건 ID는 체크아웃 범위이고 생성 시점에는 아직 조건이 없으므로 생성 요청에서는 생략하며, 완료 요청 시점에는 이미 조건이 합의되어 있으므로 완료 요청에서도 생략합니다. 조건 선택은 체크아웃 업데이트 변경 작업이며, 파생되는 모든 상태는 비즈니스 응답을 기준으로 합니다.

    currency string 필수 판매자가 판단한 시장을 반영하는 ISO 4217 통화 코드. 주소, 컨텍스트, geo IP로 결정합니다. 구매자는 신호를 제공하고 통화는 판매자가 결정합니다.

    actions object 선택 이 체크아웃에 대해 확장이 정의한 미해결 Action.

    policies Array[object] 선택 이 체크아웃의 항목에 적용되는 정책(예: 반품/환불 조건). applies_to 대상은 응답 루트를 기준으로 하며, 없거나 비어 있으면 links[]의 URL을 참조합니다.

    Buyer Consent Extension¶

    Consent Purpose¶

    특정 목적(예: 마케팅, 분석)에 대한 구매자의 동의 결정. 현재의 이진 상태, 그 출처(비즈니스 기본값 또는 플랫폼이 수집한 구매자 결정), 사람이 읽을 수 있는 맥락, 그리고 결정 범위를 특정 채널·벤더·프로그램으로 좁히는 선택적 세부 항목을 담습니다.

    이름 타입 필수 여부 설명
    granted boolean 필수 이 목적에 대해 동의가 이루어졌는지 여부. 이 상태를 누가 표명했는지(비즈니스 기본값 또는 플랫폼이 수집한 구매자 선호)는 source 필드로 식별합니다.
    source string 필수 현재 granted 값을 정한 당사자를 나타냅니다. business는 비즈니스의 기본 정책을 반영한 값이고, platform은 플랫폼이 수집한 구매자의 명시적 결정을 반영한 값입니다.
    허용 값: business, platform
    description string 필수 구매자가 무엇에 동의하는지에 대한 사람이 읽을 수 있는 설명(예: 'Promotional communications across all channels').
    links Array[object] 선택 맥락을 제공하는 링크(선택 사항, 예: 개인정보 처리방침, 이용약관).
    segments object 선택 이 목적을 특정 채널, 벤더, 프로그램으로 한정하는 세부 범위(선택 사항). 키는 역 DNS 식별자입니다. 현재 UCP는 dev.ucp.consent.marketing 아래에 잘 알려진 세그먼트 식별자 두 개(dev.ucp.consent.marketing.email, dev.ucp.consent.marketing.sms)를 정의합니다. 다른 세그먼트는 벤더나 판매자의 역 DNS 규칙을 따릅니다.

    Consent Segment¶

    상위 목적의 특정 세부 항목(예: 마케팅 목적 아래의 이메일 마케팅)에 대한 구매자의 동의 결정. 이 범위에서는 상위 항목의 granted 값을 재정의합니다. 세그먼트는 더 이상 중첩되지 않습니다.

    이름 타입 필수 여부 설명
    granted boolean 필수 이 세그먼트에 대해 동의가 이루어졌는지 여부. 이 특정 범위에 한해 상위 목적의 granted 값을 재정의합니다.
    source string 필수 이 세그먼트의 현재 granted 값을 정한 당사자를 나타냅니다. business는 비즈니스의 기본 정책을 반영한 값이고, platform은 플랫폼이 수집한 구매자의 명시적 결정을 반영한 값입니다.
    허용 값: business, platform
    description string 필수 이 세그먼트 안에서 구매자가 무엇에 동의하는지에 대한 사람이 읽을 수 있는 설명(예: 'Promotional emails and exclusive offers').
    links Array[object] 선택 세그먼트별 링크(선택 사항, 예: 채널 약관 또는 개인정보 고지).

    Consent¶

    목적별 동의. 키는 역 DNS 목적 식별자입니다. UCP는 잘 알려진 목적 네 가지(dev.ucp.consent.marketing, dev.ucp.consent.analytics, dev.ucp.consent.preferences, dev.ucp.consent.sale_or_sharing)를 정의합니다. 벤더와 판매자는 자체 역 DNS 네임스페이스 아래에 목적을 추가로 정의할 수 있습니다.

    code string 선택 할인 코드. 자동 할인에서는 생략됩니다.
    title string 필수 사람이 읽을 수 있는 할인 이름(예: 'Summer Sale 20% Off').
    amount integer 필수 ISO 4217 최소 단위로 표시한 총 할인 금액.
    automatic boolean 선택 판매자 규칙에 따라 자동으로 적용되면(코드 불필요) true.
    method string 선택 배분 방식. 'each' = 항목마다 독립적으로 적용. 'across' = 금액에 비례해 나눔.
    허용 값: each, across
    priority integer 선택 할인 계산 시 적용 순서. 숫자가 낮을수록 먼저 적용됩니다(1 = 첫 번째).
    provisional boolean 선택 이 할인에 추가 검증이 필요하면 true.
    eligibility string 선택 비즈니스가 이 할인에 대해 인정한 적격성 주장. context.eligibility의 값 중 하나에 해당합니다. 코드 기반 할인과 적격성과 무관한 자동 할인에서는 생략됩니다.
    allocations Array[object] 선택 이 할인이 배분된 위치 내역. 배분 금액의 합은 총액과 같습니다.

    Fulfillment Variant¶

    풀필먼트 정보가 포함된 카탈로그 변형.

    이름 타입 필수 여부 설명
    id string 필수 이 변형을 고유하게 식별하는 전역 ID(GID). 체크아웃에서 item.id로 사용합니다.
    sku string 선택 재고와 풀필먼트를 위해 비즈니스가 할당한 식별자.
    barcodes Array[object] 선택 상호 참조와 연계를 위한 업계 표준 상품 식별자.
    handle string 선택 URL 안전 변형 핸들/슬러그.
    title string 필수 변형 표시 제목(예: 'Blue / Large').
    description object 필수 하나 이상의 형식으로 된 변형 설명.
    url string 선택 표준 변형(variant) 페이지 URL.
    categories Array[object] 선택 선택적 분류 체계 식별자가 포함된 변형 카테고리.
    price object 필수 현재 판매 가격. 가격은 quantity_unit.unit 한 단위(예: lb당, 시간당) 기준 금액이며, quantity_unit이 없으면 each 기준입니다. 라인 합계는 price × quantity × 10^-scale이며 비즈니스가 한 번 계산하고 반올림합니다. 권위 있는 값은 여전히 totals입니다.
    quantity_unit any 선택 이 변형의 quantity가 표시되는 판매 기준입니다. 기본 판매 기준은 each이며, 기계적 정체성은 (C62, 0)입니다. C62는 one/each를 뜻하는 UN/CEFACT Rec20 코드입니다. 카탈로그 기술자가 없으면 이 기본값을 뜻합니다. increment는 스텝 단위의 주문 단위를 알립니다(예: scale 2에 increment 25이면 0.25 단위의 배수로 판매).
    list_price object 선택 할인 전 정가(취소선 표시용).
    unit_price object 선택 선반 표시 방식의 가격 비교에 쓰는 표준 측정 단위당 가격입니다. 단위 가격이 적용되지 않으면 생략할 수 있습니다(MAY).
    availability object 선택 변형의 구매 가능 여부.
    options Array[object] 선택 이 변형을 정의하는 옵션 값(예: Color: Blue, Size: Large).
    media Array[object] 선택 변형 미디어(이미지, 동영상, 3D 모델). 첫 번째 항목이 목록에 노출되는 대표 미디어입니다.
    rating object 선택 변형 평점.
    tags Array[string] 선택 분류와 검색을 위한 변형 태그.
    metadata object 선택 표준 변형 모델을 확장하는 비즈니스 정의 사용자 데이터.
    seller object 선택 이 변형의 판매자 맥락(선택 사항).
    fulfillment object 선택 카탈로그 변형을 풀필먼트하는 방식. 체크아웃 fulfillment와 같은 구조입니다.

    categories Array[string] 선택 상품 카테고리로 필터링합니다(OR 논리 — 나열된 카테고리 중 하나라도 속한 상품과 일치). 값은 상품 카테고리 항목의 value 필드와 비교합니다. 유효한 값은 검색 결과의 categories 필드, 판매자 문서, 또는 비즈니스가 따를 수 있는 표준 분류 체계에서 찾을 수 있습니다.
    price object 선택 context.currency 통화로 표시한 가격 범위 필터입니다. context.currency가 표시 통화와 같으면 비즈니스는 필터를 그대로 적용합니다. 다르면 비즈니스는 적용 전에 필터 값을 표시 통화로 변환해야 합니다(SHOULD). 변환을 지원하지 않으면 필터를 무시할 수 있으며(MAY), 이 사실을 메시지로 알려야 합니다(SHOULD). context.currency가 없으면 필터의 통화 단위가 모호하므로 비즈니스는 필터를 무시할 수 있습니다(MAY).

    이름 타입 필수 여부 설명

    context object 선택 관련성 판단과 현지화를 위한 잠정적 구매자 신호로, 권위 있는 데이터가 아닙니다. 검증된 입력(예: 배송 주소)이 없으면 비즈니스는 이 값을 사용해야 하며(SHOULD), 더 신뢰도 높은 신호(인증된 계정, 위험 탐지)나 규제 제약(수출 통제)과 맞지 않으면 무시하거나 우선순위를 낮출 수 있습니다(MAY). 자격 판단과 정책 적용은 반드시 체크아웃 시점에 구속력 있는 거래 데이터로 수행해야 합니다(MUST). 컨텍스트는 개인을 식별할 수 없어야 하며(SHOULD), 단계적으로 공개할 수 있습니다. 초기에는 대략적인 신호를, 세션이 진행되면서 더 세밀한 정보를 제공합니다. 더 세밀한 데이터(배송 주소, 청구 주소)가 컨텍스트보다 우선합니다.
    signals object 선택 승인과 악용 방지를 돕기 위해 플랫폼이 제공하는 환경 데이터. 값은 구매자가 주장한 내용이어서는 안 됩니다(MUST NOT). 플랫폼은 직접 관찰했거나 독립적으로 검증 가능한 제3자 증명에 근거한 신호를 제공합니다. 여러 확장이 공유 네임스페이스에 값을 추가할 때 출처를 보장하고 충돌을 막기 위해, 모든 신호 키는 반드시 역도메인 이름을 사용해야 합니다(MUST).
    attribution object 선택 플랫폼이 내보내는 추천 및 전환 이벤트 맥락: 캠페인 식별자, 클릭 ID, source/medium 마커 등. 브라우저 기반 흐름에서 플랫폼이 URL 쿼리 매개변수로 전달하는 것과 같은 매개변수입니다.
    filters object 선택 검색 결과를 좁히는 필터 조건. 지정한 모든 필터는 AND 논리로 결합됩니다.

    actions object 선택 이 체크아웃에 대해 확장이 정의한 미해결 Action.
    messages Array[object] 선택 체크아웃 세션 상태에 대한 오류·정보 메시지 목록.
    links Array[object] 필수 플랫폼이 표시할 링크(개인정보처리방침, 이용약관). 법적 준수를 위해 필수입니다.
    policies Array[object] 선택 이 체크아웃의 항목에 적용되는 정책(예: 반품/환불 조건). applies_to 대상은 응답 루트를 기준으로 하며, 없거나 비어 있으면 links[]의 URL을 참조합니다.
    expires_at string 선택 RFC 3339 만료 타임스탬프입니다. 보내지 않으면 기본 TTL은 생성 시점부터 6시간입니다.
    continue_url string 선택 체크아웃 핸드오프와 세션 복구용 URL. status가 requires_escalation이면 반드시 제공해야 합니다(MUST). 형식과 가용성 요구 사항은 명세를 참고하세요.
    payment object 선택 핸들러를 포함한 결제 구성.
    order object 선택 이 체크아웃 세션으로 생성된 주문의 세부 정보.
    fulfillment object 선택 풀필먼트 세부 정보.

    기능(Capability)¶

    이 객체는 기능 또는 확장 하나를 설명합니다. 디스커버리 프로필과 응답의 capabilities 배열에 나타나며, 맥락마다 필수 필드가 조금씩 다릅니다.

    기능(디스커버리)¶

    디스커버리 프로필에 나타나는 형태입니다.

    플랫폼 수준 디스커버리를 위한 전체 기능 선언. 에이전트가 가져갈 spec/schema URL을 포함합니다.

    이름 타입 필수 여부 설명
    version string 필수 YYYY-MM-DD 형식의 엔티티 버전.
    spec string 필수 사람이 읽을 수 있는 명세 문서의 URL.
    schema string 필수 이 엔터티의 구조와 페이로드를 정의하는 JSON Schema의 URL.
    id string 선택 이 엔터티 인스턴스의 고유 식별자. 인스턴스가 여러 개일 때 구분하는 데 사용합니다.
    config object 선택 엔티티별 구성. 구조는 각 엔티티의 스키마가 정의합니다.
    extends OneOf[string, array] 선택 이 항목이 확장하는 상위 기능. 확장에는 있고 루트 기능에는 없습니다. 상위가 여럿인 확장은 배열을 사용합니다.
